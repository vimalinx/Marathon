Marathon 现在到底是怎么跑起来的

你本地的控制台是真正能操作系统的那一面；Pages 只是只读投影。

一眼看懂系统边界

先把“本地能控制什么”和“外部能看到什么”分开，不然很容易把这两个面混在一起。

Marathon Core

运行在你本机。它真正管理容器、启动 agent、同步 run 日志、保存轮次结果，并且提供你现在能操作的本地控制台。

本地控制台

入口就是 ./scripts/start_web_ui.sh。这里能看总览、容器详情、AI 账号、绑定关系，也能发起和停止本地 run。

公开快照站

不是在线控制台，也不是远端 agent runtime。它只是把 repo 里的公开状态导出成静态页面，再同步到 GitHub Pages。

每小时同步器

本机 `systemd --user` timer 每小时导出一次快照，提交到 gh-pages，所以外站是“按小时刷新”的，不是实时直播。

你现在本地能用的控制面板

结论很简单：有，而且这个页面本身就是挂在那套本地控制台下面的一个静态页。

01

启动本地控制台

命令是 ./scripts/start_web_ui.sh。默认地址是 http://127.0.0.1:8765。

02

你在本地真正能做的事

看总览、看容器详情、创建 run、停止 run、看 AI 账号、绑定容器到账号。这些都发生在你本机，不是在 GitHub Pages 上。

03

GitHub Pages 不负责控制

Pages 那边只负责展示。它不会起容器、不会调用模型、不会替你执行命令，也没有你本地控制台的那些按钮和 API。

关键目录速查

如果你以后想继续扩这个系统，下面这些目录就是最值得记住的锚点。

host/web_ui.py

本地控制台服务端。总览、容器详情、AI 账号页、创建 run、停止 run 等入口都在这里。

host/static/

本地控制台前端静态资源。你现在看到的总览页、容器页、账号页、这张架构页都在这里。

runs/

run 级别的核心归档。每次运行的状态、blog、events、最新动作、输出都在这里。

state/agent_accounts/

AI 公开身份层。GitHub Pages 上展示的 agent 页面，主要就是从这里投影出去。

host/public_site.py

把本地状态导出成公开静态快照的投影器。它不提供在线运行，只负责导出。

host/github_pages_sync.py

每小时同步器。导出静态站、提交到 gh-pages、再 push 到 GitHub。

这张页是单文件中文架构总览，挂在本地控制台里；真正的公开站还是外面的 GitHub Pages 快照。

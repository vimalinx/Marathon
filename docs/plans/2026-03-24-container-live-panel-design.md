# Container Live Panel Design

**Goal:** 让容器详情页一眼看出任务是否正在运行，并把 AI 最近一次可见思路与实时轨迹放到主界面，而不是埋在原始日志里。

## 用户意图

当前详情页能看状态、输出和日志，但两个关键问题还没解决：

- “现在到底是不是在跑” 不够醒目。
- AI 的可见思路主要还藏在输出框和日志里，必须像看终端一样去翻。

用户要的是已经成型的外部界面，而不是继续把主要阅读路径放在终端样式区域里。

## 设计原则

1. 运行状态必须在首屏最醒目。
2. 把 AI 最近一次可见思路、当前动作、实时轨迹放到首屏主区。
3. 原始日志继续保留，但降级成辅助区。
4. 不伪造隐藏 CoT，只展示现在系统真实可读到的可观测流：
   - `latest_response_text`
   - `latest_action`
   - `recent_rounds`
   - `live.stdout`
   - `live.stderr`
5. 页面自动刷新，避免用户手动点刷新。

## 信息架构

### 顶部状态区

- 大号任务状态
- 当前 run id
- 运行方式
- 已完成轮次
- 更新时间
- 自动刷新状态

### AI 实时思路区

- AI 最新思路
  - 以 `latest_response_text` 为主
  - 没有时回退到最近摘要
- 当前动作
  - `latest_action.summary`
  - 最近命令
  - 返回码 / 工具结果
- 实时轨迹
  - 最近 stdout / stderr 行
  - 让用户在一轮尚未结束时也能看见“正在干嘛”

### 资源区

- 保留容器资源指标

### 最近几轮

- 继续保留，但更像事件列表

### 原始日志

- 继续保留 tab 切换
- 文案降级为“原始日志”

## 交互

- 有活动任务时每 2.5 秒自动刷新
- 没有活动任务时每 10 秒自动刷新
- 页面隐藏时暂停高频刷新
- 手动刷新按钮继续保留

## 范围控制

这次不做：

- WebSocket / SSE 真流式接口
- 模型内部隐藏推理链展示
- 设计实验室改版
- 新的后端持久化结构

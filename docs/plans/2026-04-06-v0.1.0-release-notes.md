# Marathon v0.1.0 Release Notes

## Summary

`v0.1.0` is the first public open-source release of Marathon, with `Marathon Core` as the main supported surface.

This release packages the local container runtime, host-side orchestration, operator Web UI, nightly execution path, and the minimum contributor/release scaffolding needed for a public repository.

## Highlights

### Container-first operator UI

The main UI is now centered on sandboxes and runs rather than a generic dashboard. You can:

- start and stop containers
- launch AI on an existing container
- inspect recent rounds, raw trace, and mirrored logs
- retry failed runs from the detail view

### Runtime controls

You can now configure:

- max rounds
- round pacing
- max runtime
- total token budget
- per-response token limit

These controls are surfaced in the UI and enforced through the host/container execution path.

### Better model ergonomics

The new-task flow now supports:

- saving model parameters for reuse
- testing model connectivity before launch
- explicit provider configuration without repository-level hardcoded defaults

### Failure handling and diagnostics

The runtime now retries malformed model action payloads multiple times before failing a round, and preserves invalid-response evidence for debugging.

### Open-source packaging

The repository now includes:

- MIT license
- contributing guide
- security policy
- code of conduct
- issue templates
- PR template
- basic GitHub Actions test workflow

## Supported Scope

For `v0.1.0`, the primary supported surface is:

- `Marathon Core`

These areas remain available but should still be considered experimental:

- `Marathon Site`
- `design-lab`
- GitHub Pages snapshot publishing flow

## Verification Snapshot

Release readiness was validated with:

```bash
python3 -m pytest -q
```

## Upgrade / Setup Notes

- `MARATHON_BASE_URL` must be set explicitly
- `MARATHON_API_KEY` must be set explicitly
- Web UI startup now refuses to hide port conflicts on `8765`

## Known Limits

- The project still assumes a local environment with LXC and `sudo -n` configured
- Experimental surfaces are present in the repo but are not yet held to the same stability bar as `Marathon Core`

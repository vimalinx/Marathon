# Run Index Active Plan

**Status:** completed
**Owner:** Codex
**Branch / Worktree:** current workspace
**Last Updated:** 2026-04-07
**Related Design:** `docs/plans/2026-04-07-run-index-design.md`

**Goal:** Add a SQLite-backed query index for host run data and route core operator read paths through it.

**Architecture:** `host/run_index.py` becomes a projection layer over the existing `runs/` mirror tree. It indexes per-run summaries, round posts, events, and artifacts into SQLite. `host/web_ui.py` uses that layer for `overview` and `run_detail` while keeping runtime-only container metrics live. The file mirror remains the source of truth.

**Verification:**

- `python3 -m pytest tests/test_web_ui.py tests/test_orchestrator.py -q`
- `python3 -m pytest -q`

**Out Of Scope:**

- Replacing file-based collection
- Public site migration to the index
- Remote ingestion

---

## Current Slice

**Why now:** The current file-only collection backend is functional, but the query path is becoming the bottleneck for richer diagnostics and future server-side collection evolution.

**Stop condition:** `overview` and `run_detail` can read indexed run data from SQLite, the index refreshes from `runs/`, and the existing API contract remains intact.

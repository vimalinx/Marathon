# Dashboard Primary Run Design

**Goal:** 把总览页从“平均展示所有容器”改成“先突出当前最重要的运行，再快速扫其他容器”。

## 用户意图

用户已经确认总览页要采用：

- 顶部一个主运行大卡
- 下方其余容器简卡

原因很直接：

- 首屏应该先回答“现在谁在跑”
- 其次回答“AI 正在想什么、最近在做什么”
- 其他容器只需要快速扫一眼，不该和当前主运行平权

## 设计原则

1. 首页首屏只强调一个主运行。
2. 主运行卡用大状态 + 最新可见意图 + 最近动作。
3. 其他容器全部降级成简卡。
4. 继续沿用现有黑白米色体系，不做花哨控制台风格。
5. 增加自动刷新，但保持克制：
   - 有活动任务时更快
   - 没有活动任务时更慢

## 信息架构

### 当前主运行

- 大状态
  - 正在运行 / 最近一次运行 / 未启动
- 主容器名
- run id
- 运行方式
- 已完成轮次
- 更新时间
- 模型
- 自动刷新节奏
- 最新可见意图
- 最近动作 / 最近输出摘录
- 操作入口
  - 看详情
  - 基于此新建

### 整体情况

- 容器总数
- 正在运行的容器
- 正在执行的任务
- 最新变化

### 其他容器

- 保留简卡
- 每张卡只显示：
  - 容器名
  - 状态
  - 轮次
  - 更新时间
  - 一段简短摘要

## 数据来源

全部基于现有 `/api/overview`：

- 主运行容器选择规则：
  1. 优先活动任务
  2. 否则最近一次运行
  3. 否则第一个容器
- 主运行意图来源：
  - `latest_action_summary`
  - `latest_response_preview`
  - `last_summary`

## 范围控制

这次不做：

- 首页完整日志面板
- 首页多主运行并排
- 首页图表
- 新后端接口
